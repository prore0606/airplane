## 1. 배경 및 목적

### 문제 정의
인천공항 출국자는 출국 당일 평균 4~6가지 반복 작업을 수동으로 처리한다.
- 체크인 여부 확인, 수하물 마감 시간 계산, 보안검색 대기 예측, 귀국 후 주차 위치 기억 등
- 정보가 분산(항공사 앱, 공항 안내판, 메모 앱)되어 있어 놓치는 경우 발생

### 솔루션
항공권 OCR 스캔 한 번으로 모든 출국 프로세스를 AI가 자동 연결하는 **원스톱 출국 동반자 앱**

### 목표
- **1차 목표**: 인천공항 출국자 대상 로컬 기반 MVP 구현
- **성공 지표**: 앱 설치 후 항공권 스캔 완료율 70% 이상

## 2. 타깃 유저

| 구분 | 내용 |
|------|------|
| Primary | 인천공항 이용 국내 출국자 (연 3,000만 명) |
| Secondary | 해외 여행 자주 가는 직장인 (연 4회 이상) |
| 제외 | 도착 여행객, 화물, 항공 관계자 |

### 유저 페르소나
**김민준 (32세, 직장인)**  
- 분기 1회 해외 출장, 매번 수하물 마감 놓칠까봐 불안
- 귀국 후 주차한 곳 잊어버려 30분 이상 헤맨 경험

## 3. 유저 스토리

| ID | As a... | I want to... | So that... |
|----|---------|--------------|------------|
| US-01 | 출국자 | 항공권 사진을 스캔하면 | 항공편 정보가 자동 등록되길 원한다 |
| US-02 | 출국자 | AI가 체크리스트를 자동 생성하면 | 준비물을 빠짐없이 챙길 수 있다 |
| US-03 | 출국자 | 실시간 항공편 상태를 알림으로 받으면 | 게이트 변경·지연을 놓치지 않는다 |
| US-04 | 출국자 | 주차 위치를 GPS로 저장하면 | 귀국 후 차를 빠르게 찾을 수 있다 |
| US-05 | 출국자 | 보안검색 대기 현황을 보면 | 최적 시간에 이동할 수 있다 |
| US-06 | 출국자 | 캐릭터가 레벨업하면 | 여행을 더 즐겁게 기록할 수 있다 |

## 4. 기능 요구사항 (Functional Requirements)

### 4.1 우선순위 (MoSCoW)

#### Must Have (1차 MVP)
| ID | 기능 | 설명 |
|----|------|------|
| FR-01 | 항공권 OCR 스캔 | 사진·PDF에서 항공편 정보 자동 추출 |
| FR-02 | AI 체크리스트 | 목적지·기간 기반 맞춤 준비물 자동 생성 |
| FR-03 | 실시간 항공편 조회 | 인천공항 공공데이터 API 연동 |
| FR-04 | 주차 GPS 저장 | 현재 위치 저장 + 귀국 후 안내 |
| FR-05 | 푸시 알림 | 게이트 변경·지연·수하물 마감 알림 |
| FR-06 | 하단 탭 내비게이션 | 홈/항공편/지도/캐릭터/MY |

#### Should Have (2차)
| ID | 기능 |
|----|------|
| FR-07 | 캐릭터 레벨업 / 배지 시스템 |
| FR-08 | 친구 초대 / 소셜 기능 |
| FR-09 | 공항 시설 지도 (면세점·라운지·식당) |

#### Could Have (3차)
| ID | 기능 |
|----|------|
| FR-10 | 귀국 차량 복귀 내비 연동 |
| FR-11 | 다국어 지원 (EN/JP/CN) |

#### Won't Have (현재 범위 외)
- 항공권 예매 기능
- 환율 거래

## 8. 데이터 모델 요약

총 14개 테이블 — 상세 스키마 → [`database.sql`](database.sql)

```
users → flights → flight_alert_settings
     → parking_records
     → checklists → checklist_items
     → notifications
     → user_characters → badges → user_badges
     → pedometer_logs
     → friendships
     → invite_codes
```
